# 知识口播

目标是让观众真正理解、记住并能应用，而不是把资料压缩成朗读稿。

## 适用条件

- 有明确问题、可验证结论、专业经验、演示或案例。
- 核心价值主要来自解释，而非事件本身的不可预测过程。
- 创作者愿意通过观点、示范或判断承担“为什么由我讲”的责任。

## 推荐结构

按题目需要取舍，不固定段数：

1. **兑现承诺**：用结论片段、问题现场、反例或演示告诉观众会得到什么。
2. **建立认知地图**：说明问题边界、必要概念和接下来怎么走。
3. **逐层解释**：每层只完成一个认知动作；概念后立刻接例子、证据或可视化。
4. **压力测试**：处理常见误解、反例、适用边界或不确定性。
5. **落到使用**：告诉观众如何判断、尝试或继续学习。
6. **收束**：回到开头承诺，用一句可复述的话形成记忆点。

## 写作检查

- 每个专业词第一次出现时用普通语言定义。
- 数字要有尺度、比较对象和来源；不能只用“大量、显著、研究表明”。
- 解释“为什么”的段落至少包含机制、示例或演示之一。
- 观点、事实、推测和个人经验在措辞上可区分。
- 不用假想反对者制造虚假冲突。
- 画面承担解释任务：图、实物、屏录、手写、测试或出处，而不是无关 B-roll。

## 音画设计

| 音频任务 | 优先画面 |
|---|---|
| 定义概念 | 简图、实物、关键词分解 |
| 比较差异 | 同尺度并列、表格、实测 |
| 解释机制 | 流程图、逐步演示、因果链 |
| 引用证据 | 来源卡片、关键图表、限定语 |
| 给出方法 | 屏录、步骤卡、真实操作 |

口播者出镜应建立关系或强调判断；当画面能更清楚地解释时，让画面接管信息。

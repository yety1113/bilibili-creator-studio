# 脱口秀 / 喜剧独白

这里的“脱口秀”指以创作者个人观点为核心的喜剧独白。它可以承载知识或生活题材，但笑点不能替代事实，事实也不能替代喜剧结构。

## 核心单位

- **主题**：谈什么。
- **态度**：创作者对此真正觉得奇怪、愤怒、尴尬、羡慕或矛盾的是什么。
- **前提 premise**：把态度压成一句可争辩的观察。
- **铺垫 setup**：只提供理解笑点所需的信息。
- **笑点 punch**：改变预期、解释框架或意义。
- **追加 tag**：在同一前提上继续升级，不重复解释。
- **表演 act-out**：用声音、动作、角色或场景把观点具体化。
- **回扣 callback**：后段重新激活前面建立的元素。

## 发展流程

1. 从真实观察写 10–20 条“我发现 / 我讨厌 / 我不理解 / 最尴尬的是”。
2. 找到最鲜明且可承担的态度，写成一句前提。
3. 为前提列出现实例子、矛盾、极端化、类比、误解和角色声音。
4. 先写逻辑清楚的铺垫，再尝试多种笑点方向。
5. 把最强笑点前移，删除解释笑点的句子。
6. 用朗读或小范围试讲记录真实反应，再决定保留、换词或重写。

## 结构

整段仍需论证或故事推进：开场建立人物与前提，中段通过例子和升级扩大矛盾，后段出现更深的自我暴露、观点翻转或回扣。不要把彼此无关的段子用主题词勉强串联。

## 安全与边界

- 优先“向上打”或自我暴露；涉及弱势身份、灾难、疾病、未成年人和真实私人个体时提高审查门槛。
- 区分角色台词与作者立场，但不能用“只是玩笑”掩盖事实性诬陷、骚扰或仇恨。
- 不伪造真实人物言行。需要组合或虚构时明确艺术处理。
- 测试笑点是否依赖观众不了解事实；若是，补足事实或放弃笑点。
- 不承诺固定“笑点密度”。节奏由表演、受众和主题决定，以桌读/试讲结果为准。

## 交付两个版本

1. **工作稿**：标注 premise / setup / punch / tag / act-out / callback，便于诊断。
2. **表演稿**：移除结构标签，保留停顿、重音、表情和动作提示。

语气可以锋利，但观点必须属于创作者，而不是由模板替创作者发怒。

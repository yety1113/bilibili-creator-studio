- Skill 结构、frontmatter、命名和占位符校验：通过。
- 插件 manifest、路径、必填元数据和组件发现校验：通过。

## 场景走查

### 1. 知识口播：普通人现在是否需要购买 NAS

- 当前价格、产品参数和安全建议触发实时研究。
- 在推荐购买前建立“使用场景—成本—替代方案—风险”的证据链。
- 先给标题/封面/开头统一承诺，再产出解释结构。
- 对无法核验的故障率或市场数据标记未知，不自动打星。
- 结果：通过。

### 2. Vlog：记录第一次独自搬家

- 以目标、限制、行动和变化驱动，而非按时间流水账。
- 区分可预写旁白、拍摄清单和不可预写的真实反应。
- 对补拍、他人隐私、地址与票据信息设置门禁。
- 缺少关键素材时在预览中给替代方案，不捏造冲突。
- 结果：通过。

### 3. 脱口秀：成年人为什么害怕体检

- 从个人态度与矛盾发展 premise、setup、punch、tag、act-out 和 callback。
- 健康事实仍需独立核验，不用笑点替代医学证据。
- 对疾病、真实个体与弱势群体提高审查门槛。
- 同时交付工作稿与干净表演稿的规则明确。
- 结果：通过。

### 4. 声线边界：要求“完全写成某位在世 UP 主的风格”

- 不进行身份化模仿；转换为句长、能量、冷面程度、观察型幽默等抽象参数。
- 先给短样，再扩写长稿。
- 事实和限定词不因风格转换而改变。
- 结果：通过。

### 5. 旧稿审阅：只检查，不要重写

- 路由到 Audit；按承诺、可信、可懂、推进、可看、可拍、合规七项输出问题。
- 尊重“不重写”的范围，仅给分级问题与最小修复建议。
- 结果：通过。

## 已知边界

- v0.1.0 不直接读取用户的 B站创作中心账号数据；用户需粘贴、导出或截图提供。
- v0.1.0 不生成封面图、分镜图或成片，只生成足以进入这些阶段的文本方案。
- 时长脚本只做粗估；最终以创作者本人计时桌读为准。
- 平台规则与热点会变化，执行具体项目时必须重新查证，不能只依赖设计期来源。
